# 03. Database Connection & Data Models

In this section, we will establish a connection to PostgreSQL using **GORM**, define our data models with UUID primary keys and relationship constraints, and create a standalone migration script.

---

## 1. Connecting to PostgreSQL (`initializers/connectDB.go`)

Create `initializers/connectDB.go`. This module opens a connection pool to PostgreSQL using the settings loaded from `Config`.

```go
package initializers

import (
	"fmt"
	"log"

	"gorm.io/driver/postgres"
	"gorm.io/gorm"
	"gorm.io/gorm/logger"
)

var DB *gorm.DB

// ConnectDB initializes the PostgreSQL connection using GORM
func ConnectDB(config *Config) {
	var err error
	dsn := fmt.Sprintf(
		"host=%s user=%s password=%s dbname=%s port=%s sslmode=disable TimeZone=UTC",
		config.DBHost,
		config.DBUser,
		config.DBUserPassword,
		config.DBName,
		config.DBPort,
	)

	DB, err = gorm.Open(postgres.Open(dsn), &gorm.Config{
		Logger: logger.Default.LogMode(logger.Info),
	})

	if err != nil {
		log.Fatal("Failed to connect to the Database! \n", err.Error())
	}

	log.Println(" Connected Successfully to the Database")
}
```

### Explaining the Connection Code:

- **`dsn` (Data Source Name)**: Specifies host, user credentials, database name, and port. Setting `sslmode=disable` is standard for local Docker development.
- **`logger.Info`**: Enables SQL query logging in your terminal so you can see exact queries generated by GORM during development.
- **`DB` global pointer**: Holds the active connection pool.

## 2. Defining User Models & DTOs (`models/user.model.go`)

Create `models/user.model.go`. This file defines both the database schema for the `users` table and the Request / Response Data Transfer Objects (DTOs).

```go
package models

import (
	"time"

	"github.com/google/uuid"
)

// User represents the database schema for the 'users' table
type User struct {
	ID        *uuid.UUID `gorm:"type:uuid;default:gen_random_uuid();primary_key"`
	Name      string     `gorm:"type:varchar(255);not null"`
	Email     string     `gorm:"uniqueIndex;not null;type:varchar(255)"`
	Password  string     `gorm:"not null;type:varchar(255)"`
	Role      string     `gorm:"type:varchar(50);default:'user';not null"`
	Provider  string     `gorm:"not null;default:'local'"`
	Photo     string     `gorm:"not null;default:'default.png'"`
	Verified  bool       `gorm:"not null;default:false"`
	CreatedAt time.Time  `gorm:"not null"`
	UpdatedAt time.Time  `gorm:"not null"`
}

// SignUpInput holds validation tags for new user registration
type SignUpInput struct {
	Name            string `json:"name" binding:"required"`
	Email           string `json:"email" binding:"required,email"`
	Password        string `json:"password" binding:"required,min=8"`
	PasswordConfirm string `json:"passwordConfirm" binding:"required,eqfield=Password"`
	Role            string `json:"role"`
	Photo           string `json:"photo"`
}

// SignInInput holds validation tags for logging in
type SignInInput struct {
	Email    string `json:"email"  binding:"required,email"`
	Password string `json:"password"  binding:"required"`
}

// UserResponse defines the safe user representation returned to clients
// (Notice: Password is intentionally omitted to avoid credential leaks!)
type UserResponse struct {
	ID        uuid.UUID `json:"id,omitempty"`
	Name      string    `json:"name,omitempty"`
	Email     string    `json:"email,omitempty"`
	Role      string    `json:"role,omitempty"`
	Photo     string    `json:"photo,omitempty"`
	Provider  string    `json:"provider"`
	CreatedAt time.Time `json:"created_at"`
	UpdatedAt time.Time `json:"updated_at"`
}
```

### Why UUID Primary Keys?

Using `uuid.UUID` with `gen_random_uuid()` prevents:

1. **ID Enumeration attacks**: Attackers guessing sequential integer IDs (`/users/1`, `/users/2`).
2. **Key collisions in distributed systems**: Independent nodes can generate distinct IDs safely without cross-database synchronization.

## 3. Defining Post Models & DTOs (`models/post.model.go`)

Create `models/post.model.go` to store blog posts or articles authored by users.

```go
package models

import (
	"time"

	"github.com/google/uuid"
)

// Post represents the database schema for the 'posts' table
type Post struct {
	ID        *uuid.UUID `gorm:"type:uuid;default:gen_random_uuid();primary_key"`
	Title     string     `gorm:"type:varchar(255);uniqueIndex;not null"`
	Content   string     `gorm:"not null"`
	Image     string     `gorm:"not null"`
	User      uuid.UUID  `gorm:"type:uuid;not null"`
	CreatedAt time.Time  `gorm:"not null"`
	UpdatedAt time.Time  `gorm:"not null"`
}

// CreatePostInput defines request payload validation when creating a post
type CreatePostInput struct {
	Title   string `json:"title" binding:"required"`
	Content string `json:"content" binding:"required"`
	Image   string `json:"image" binding:"required"`
	User    string `json:"user,omitempty"`
}

// UpdatePostInput defines request payload validation when updating a post
type UpdatePostInput struct {
	Title   string `json:"title"`
	Content string `json:"content"`
	Image   string `json:"image"`
	User    string `json:"user,omitempty"`
}
```

## 4. Standalone Migration Script (`migrate/migrate.go`)

It is good practice to separate database schema migrations from normal server startup.

Create `migrate/migrate.go`:

```go
package main

import (
	"fmt"
	"log"

	"golang-gorm-postgres/initializers"
	"golang-gorm-postgres/models"
)

func init() {
	config, err := initializers.LoadConfig(".")
	if err != nil {
		log.Fatal("Could not load environment variables: ", err)
	}

	initializers.ConnectDB(&config)
}

func main() {
	// Enable PostgreSQL pgcrypto extension for gen_random_uuid()
	initializers.DB.Exec("CREATE EXTENSION IF NOT EXISTS \"pgcrypto\"")

	// Run AutoMigrate for both models
	err := initializers.DB.AutoMigrate(&models.User{}, &models.Post{})
	if err != nil {
		log.Fatal("Migration failed: ", err)
	}

	fmt.Println(" Migration completed successfully!")
}
```

### Running the Migration:

Whenever you change your models or on initial setup:

```bash
go run migrate/migrate.go
```

This will automatically create tables, constraints, and indexes in PostgreSQL.
